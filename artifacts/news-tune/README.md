# Настроечный набор новостного Pulse — D2

**предварительная агентская разметка, настроечный набор**. Это не человеческий эталон и не проверочная выборка. Подготовлено 24 сентября 2026 года для настройки правил; результаты на этих примерах нельзя выдавать за независимую оценку качества.

Прочитаны `AGENTS.md`, `docs/product.md` и целиком `docs/plans/news-first-pulse-agent-prompt.md`. Разметка сделана по исходным текстам базы. `artifacts/news-eval/` прочитан только для исключения его записей и повторения формата и схемы `expected`; его ответы не копировались в настройки. `artifacts/news-pulse/eval/` не открывался. Продуктовые классификаторы и их результаты не использовались, сетевых LLM-вызовов не было.

## Состав

|---|---:|

| Релевантные новости / отрицательные примеры | 34 / 9 |
| Комментарии | 24 |
| Связь с событием / авторским тезисом | 1 / 5 |

Все 12 отрицательных пар имеют общую сущность: семь сравнивают отчёты ETH-ETF разных периодов, остальные — разные операции и этапы ZEC, разные NFT-коллекции либо ETF и фьючерсы с ETH. Это превышает минимум шести трудных отрицательных пар. Среди положительных пар 11 межканальных; p15/p16 — повторный анонс в одном канале. Положительные пары представляют девять основных эпизодов, поэтому 12 пар не равны 12 независимым событиям.

Тем AAVE и Arc нет. При отборе исключались также тексты с отдельными словами AAVE, Arc, Arclings и ArcHub; это дополнительно проверяет скрипт. Все тексты сохранены целиком, без редактирования для улучшения меток.

## Примеры и границы решений

- **Разные формулировки одного события:** p4240 перечисляет четыре кошелька и отдельные суммы вывода ZEC, p12853 даёт одну строку о четырёх кошельках и 32 293 ZEC. Сумма четырёх операций совпадает точно. Это распространение одного сообщения, не доказательство независимого подтверждения.
- **ETH-ETF:** развёрнутые сообщения @cryptoattack24 сопоставлены с таблицами @rawa_imagination; p12911 добавляет третий канал с точной суммой 269 980 000 вместо округлённых 270 млн. При совпадении сущности разные торговые дни размечены отдельно. Старые значения в хвосте таблицы не размечены вторичными событиями.
- **Неоднозначная положительная пара:** p4263/p13911 предварительно отнесены к пятничному притоку: в воскресном посте повторяются 144 млн ETH, 433 млн BTC и последовательности прошлых потоков субботнего отчёта. Явной даты торговой сессии в таблице нет. Перед превращением набора в человеческий эталон эту пару нужно проверить; нельзя вывести общее правило «одинаковые суммы всегда означают одно событие».
- **Многотемные дайджесты:** p14/p7943 — WL zkGhosts; p15/p16 — минт CypherSquad 22 сентября 20:00 МСК; p4271/p7811 — строка о фьючерсах Мосбиржи с ETH внутри точной перепечатки календаря. `event_id` здесь означает выбранный для настройки эпизод, а не весь дайджест.
- **Голосование и апгрейд:** p7336 сообщает о предстоящем завершении голосования NU7; p7734 содержит обзор роста ZEC и отдельный план апгрейда 5 ноября. Их нельзя склеивать в одно событие лишь по NU7. Дедлайн, результат голосования и активация — разные этапы. Положительная пара с результатом голосования не заявлена.
- **Котировочные подвалы:** p6993, p6994, p6997 содержат ETH только в таблице цен. Это отрицательные примеры для новостей Ethereum. Отдельный ценовой алерт p7021 о ZEC 1400 — положительный пример.
- **Промо и косвенные упоминания:** p7330 — анонс без раскрытого события; p12721 — приглашение к статье; p7009 — негативная оценка ZEC в подборке других коллекций; p4184 — прибыль трейдеров NEAR; p12867 — рост ZAMA со ссылкой о ZEC.
- **Связи обсуждений:** под p15 отдельно размечены вопросы о кошельке ZEC и реплики о ZADDR/ZecVisions. Они не становятся реакцией на выбранный минт CypherSquad. Жалоба 572131 «зек лагает» остаётся неопределённой: пользователь не различает кошелёк, площадку и сеть. Под p13841 есть возражение тезису о пробое ETH, уточнение уровня 2500, собственные ожидания по ETH и уход к теннису/BTC.

## Схема

`posts.jsonl`, `comments.jsonl`, `pairs.jsonl` повторяют структуру news-eval; пространства `id` постов и комментариев сохраняют исходные ключи, пары имеют префикс `tune-pair-`.

В посте:

- `text_raw` — значение `payload.text` после разбора внешнего JSON без дальнейших изменений; `text` — читаемый текст со снятием одного дополнительного слоя JSON-экранирования, если он есть. Скрипт сверяет обе формы с исходником.
- `expected.topics` — тема запроса, включая отрицательные случаи, а не перечень всех упомянутых активов. `relevant_news` относится к этой теме. Событие NEAR или ZAMA может иметь `event_id` при `relevant_news=false` для ZEC.
- `segments` — точные фрагменты основания с классами `event`, `redistribution`, `author_position`, `promo_service`. Индексы Unicode `[start,end)` относятся к `text`. Это не исчерпывающее разбиение: прочие темы дайджеста не размечены. Перекрытие классов допустимо.
- `event_id` — основной размеченный эпизод, `event_ids` — основной и явно размеченные вторичные эпизоды. p7734 дополнительно содержит план NU7. В парах сравнивается основной эпизод; отрицательные пары не имеют общих размеченных событий.
- `origin` и `source_role` — предварительная оценка по форме и атрибуциям. `repost` у точных копий не доказывает Telegram forward. Ранняя копия не объявляется первоисточником. Официальность каналов и независимость подтверждений не установлены.
- `stored_comments=0` значит «в базе реакция не найдена». Полнота сбора не установлена.
- `window_membership={}`: D2 не размечает временные окна и не копирует окна news-eval. Timestamp — исходное время публикации; дата события извлекается только как предварительная интерпретация содержания.

В комментарии `expected.class=participant_reaction`; `link_target` принимает `event`, `author_thesis`, `project`, `other_subject`, `topic_level_uncertain`. `subject` уточняет предмет, `reason` объясняет связь. `post_ref` указывает на пост в этом наборе. `parent_context` содержит доступный исходный ключ, время и текст непосредственного родителя; некоторые родители нужны только как контекст и не входят в 24 размеченных комментария.

В паре используются `same_event`, `event_id` (null для разных), `shared_topics`, `reason`. Решения сделаны по предмету, действию, участникам, суммам и периоду, а не одному тикеру.

## Воспроизведение и защита исходников

Из корня репозитория:

```sh
python3 artifacts/news-tune/sample.py
python3 artifacts/news-tune/sample.py --export /tmp/news-tune-reproduction
```

Для второй команды каталог должен отсутствовать. `--db /абсолютный/путь/astrafeed.db` задаёт базу явно. Нужен только Python 3 со стандартной библиотекой. Скрипт не импортирует код продукта, news-eval/sample.py или модельные результаты.

`sample.py` хранит фиксированные идентификаторы и ручные метки, повторно извлекает тексты и контекст из базы, строит JSONL детерминированно. Обычный запуск сверяет три файла побайтно, проверяет SHA-256 файлов набора из `manifest.json`, фрагменты, ссылки между записями, минимальные размеры, баланс пар, непересечение и MD5 базы до/после. Экспорт пишет только три JSONL в новый каталог; он также выполняет проверки состава и исключений. Manifest не подписан и не включает собственный хеш.

База открывается **только** через `sqlite3.connect(Path.resolve().as_uri() + '?mode=ro', uri=True)`. MD5 до и после: **`8618099125a806df376354286ccd982e`**, совпадает с `artifacts/pulse-slices.json`. Записи, миграции и меняющие базу PRAGMA не выполнялись.

Отбор кандидатов: прочитаны схема, затем `SELECT * FROM raw_item`; декодированные тексты фильтровались по ZEC/Zcash/ETH/Ethereum, после исключения news-eval. Фиксированное воспроизведение использует:

```sql
SELECT * FROM raw_item WHERE id=?;
SELECT count(*) FROM comment WHERE source_id=? AND post_id=?;
SELECT * FROM comment WHERE source_id=? AND post_id=? AND comment_id=?;
SELECT comment_key,ts,text FROM comment
WHERE source_id=? AND post_id=? AND comment_id=?;
```

Пересечения с news-eval при проверке:

| Проверка | Пересечений |
|---|---:|
| Посты по id | 0 |
| Посты по source_id + external_id | 0 |
| Посты по точному читаемому тексту | 0 |
| Комментарии, включая встроенный контекст родителей с обеих сторон | 0 |
| Размеченные комментарии по точному тексту | 0 |
| Неупорядоченные пары постов | 0 |

Разделение выполнено на уровне записей и точных текстов. Пересказы одного события другими постами и близкие по смыслу сообщения могут встречаться в обоих наборах: это **не разделение по событиям, времени или каналам** и не доказательство переноса на новые события. Набор намеренно целевой, с повышенной долей трудных примеров; доли классов не описывают реальный поток.

SHA-256 всех файлов news-eval зафиксированы перед работой и повторно сверены после неё: изменений нет. Чужие рабочие файлы не менялись, git commit/stash/checkout/reset не выполнялись. Внешняя достоверность сообщений не проверялась. В частности, противоречие месяца в p4281 сохранено. Связь с событием представлена всего одним комментарием: для устойчивой настройки таких связей этого недостаточно.
