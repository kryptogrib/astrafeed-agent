# Предмет реакции в ветке: связыватель против контекстного LLM-разбора

Исследовательский эксперимент. Отвечает на вопрос: на что реагирует комментарий — на событие поста, на тезис автора, на проект в целом или на другую тему? Цель — точнее отвечать «что комьюнити думает и почему». Production-путь не менялся. Все файлы эксперимента лежат отдельно:

- `docs/research/reaction_subject.py`
- `docs/research/reaction_subject_labels.py`
- `artifacts/reaction-subject/`
- `tests/research/test_reaction_subject.py`

## Как устроено

1. **Выборка** (`sample`). Использованы прогоны eth/zec/arc/aave за окно 2026-09-09..2026-09-23 на той же БД (md5 8618…).
   - Отобраны 31 ветка и 111 комментариев из discussion.
   - Посты из frozen gold (news-eval, news-tune) исключены.
   - Если ветка встречается в нескольких темах, она берётся один раз. Из каждой ветки — не больше 6 реплик, выбор по хешу.
   - Тип ветки определяется по выходу пайплайна:
     - news — есть события;
     - author_forecast — есть тезисы автора;
     - mixed — есть и то и другое;
     - topic_shift — нет ни того, ни другого.
   - Разбиение по хешу ветки внутри типа: dev 9 веток / test 22. Если тип представлен одной веткой, она уходит в test.
2. **Разметка** (`label`). Предварительная, её делал агент; она **закреплена в 75942e3 до написания промпта**.
   - Метки: event / author_thesis / project / other_subject / unclear, плюс skip для пустого текста.
   - 32 спорных случая отмечены `disputed` и требуют человеческой проверки.
   - Реплика из test, почти повторяющая dev, не оценивается (таких 3).
   - В test оцениваются 69 реплик: event 13, author_thesis 7, project 2, other_subject 29, unclear 18.
3. **Ветки сравнения** (`llm`, `eval`):
   - `baseline` — текущий `link_comment` без изменений. `topic_level` считается воздержанием (unclear).
   - `context` — один вызов на ветку. Модель видит пост, события и тезисы этого поста, реплики и цепочку **только предшествующих** ответов. Будущих реплик и других веток модель не видит; это проверяет тест.
     - Выход по каждой реплике: target, target_id, точный фрагмент реплики и точный фрагмент контекста.
     - Если фрагмент неточный или target_id чужой, связь понижается до unclear и помечается (`invalid_basis`).
   - `context+verify` — второй вызов на каждую ветку, где есть предложенные event-связи. Проверяющий ищет причины отклонить связь. Отклонённая связь становится unclear, но реплика остаётся в обсуждении темы.
   - `+id` — действующий production-контракт из 34a6222: event-связь должна назвать событие этого прогона. Event без target_id считается unclear. Контракт применён после того, как я увидел ответы. Это не новое правило, подобранное по test, но оговорку фиксирую.
4. Промпт v1 написан один раз. Итераций по dev не было: dev и test оба фактически отложены.
5. Запросы, ответы, meta и usage лежат в `artifacts/reaction-subject/cache/`. Повторный запуск без `--pay` — это 44 cache hit и 0 вызовов.

Сводка по предметам:

- **Реакция на событие** — главный выигрыш. Baseline не приписал событию ни одной реплики. Лучшая ветка верно приписала 9 из 13 без единой ложной event-связи.
- **Тезис автора** — 4 из 4 заявленных верны. Но только одна ветка имеет тезис, выделенный пайплайном, — «Эфир настоялся, дальше 3к» (slavik_investor/2469). В остальных случаях модель ссылается на мнение автора, которого нет в списке тезисов. Для Pulse это слабее: нечего процитировать как «тезис».
- **Проект в целом** — 0 из 3, и обе эталонные project-реплики потеряны. Категория не работает.
- **Другая тема** — 22 из 34. Главные ошибки: реплики без предмета, которые эталон считает unclear, а модель уверенно уводит в «другую тему».

### Что изменилось по существу (baseline → context+verify+id)

Все пункты ниже — примеры из test.

- **Ложные приписывания устранены (3).** Baseline отнёс к «проекту» два поста-пересказа: машинный перевод дайджеста и перепост новостей NEAR. Реплику «АКА отлично покормили, а вот Arclings походу заскамили» baseline отнёс к другой теме. Теперь первые два — «другая тема», третья — воздержание, потому что фрагмент контекста неточный.
- **Правильные связи сохранены.** У baseline верных заявленных связей не было, сохранять нечего.
- **Новые правильные связи (33).** Среди них:
  - «xaut давно же был на v4» и «Золото? Вот это поворот!» → приём золота в залог Aave;
  - «Ну зашквар или новый уровень?» → запуск Arc от Circle;
  - «ващета сегодня» → дата мейннета Arc;
  - «дальше 1500)» и «До 3к эфир подарочно выглядит» → прогноз автора «дальше 3к»;
  - «ага, Раванга это и предположила» → вывод автора об украденном ключе.
- **Новые ошибочные связи (15).** 9 реплик без предмета уверенно названы «другой темой» или «проектом»; одна реплика о другой теме названа проектом; остальное — потерянные реакции ниже.
- **Потерянные реакции.** Реплика, у которой в эталоне есть предмет, уходит из темы в «другую тему»:
  - «То бишь hype или zec 😁» — уточнение совета автора;
  - «Рекомендую посмотреть пару usdjpy к btcusdt и ethusdt…» — развитие тезиса автора;
  - «я стал откупать эфир и щитки…» — об ETH в целом;
  - «а разрабы?» — о команде Arc.

  Эти четыре реакции пропадут из ответа по теме. Ещё «готовы ректоваться?» ушла из события в проект, а «На койнгеко написали что ключ украли» стала воздержанием: событие указано неверно.
- **Отсечено проверяющим (9).**
  - пять реплик «не жирно ли работягам» модель привязала к конкурсу Extended — эталон неопределённый, спорный;
  - «согласен» — это согласие с оценкой автора, а не событие;
  - реклама депозитов fomo;
  - одна верная реакция («Вот это поворот, золото в крипте, интересно») — потеря;
  - «На койнгеко…».
- **Отсечено контрактом id.** Реплики про другие пункты дайджеста (Yield Fields, коррекция BTC) модель назвала event без id; контракт перевёл их в воздержание. На dev это же случилось с Linera, ArcHub и NFT-минтом: 10 из 11 ложных event были без id. Это расхождение словаря: модель считает событием любой факт поста, а продукту нужно событие темы.

## Ограничения

- **Разметка предварительная, одного агента.** 32 из 111 реплик спорные; на бесспорных выводы те же. Автор разметки писал и промпт. Тексты test-веток он видел при разметке, но промпт не подбирался по ответам на test.
- **Выборка мала.** В test 13 event-реплик и 7 тезисных. Ветка с выделенным тезисом одна: у остальных тезисных постов пайплайна нет комментариев. Смешанных веток и веток со сменой предмета внутри цепочки мало.
- **Каналы.** Все ветки из тех же 14 каналов; много дайджестов whitelist1 и rawa_imagination. Новые каналы, о которых сообщил пользователь, в config.yaml и БД пока отсутствуют, поэтому проверка переноса не выполнена.
- **Словарь «event».** Модель называет событием любой факт поста. Без контракта id это главный источник ложных связей (dev: 11 ложных event из 17 ошибок).
- **Категория project не работает** (0/3), а «другая тема» перехватывает реплики без предмета. Если «другую тему» по решению модели исключать из обсуждения темы, потеряются 4 из 9 тезисных и проектных реакций test.

## Рекомендация

**Массово пока не внедрять. Как следующий шаг — да, в конфигурации context + verify + контракт id и только для event- и тезисных связей.**

- На новых проверочных ветках эта конфигурация превращает «предмет не установлен» в верную связь для 9 из 13 реакций на событие и 4 из 7 реакций на тезис. Ложных event-связей нет, стоимость — копейки.
- Решения «project» и «other_subject» из модели в продукт не переносить. Такие реплики оставлять на уровне темы, как сейчас: иначе реакции пропадают из ответа.

Перед решением о внедрении:

1. Человек проверяет 32 спорные метки.
2. Второй проверочный набор — из новых каналов, когда они появятся в БД — с большим числом тезисных веток.
3. Отдельная проверка тезисов, которых пайплайн не выделил. Без выделенного тезиса Pulse нечего цитировать.

Объединение событий, инфраструктура и продуктовые пороги не затрагивались.
