# Xpoz для публикаций и ответов X/Twitter

Проверено по документации Xpoz 25 сентября 2026 года; затем выполнены четыре пробных вызова к данным с ключом из локального окружения.

## Доступ и методы

- Для фонового Python-сборщика: `pip install xpoz`, ключ из [Xpoz get-token](https://xpoz.ai/get-token) в `XPOZ_API_KEY`, `XpozClient` или `AsyncXpozClient`. SDK работает через MCP endpoint `https://mcp.xpoz.ai/mcp`; сам MCP поддерживает OAuth. [Quickstart SDK](https://docs.xpoz.ai/sdks/python/quickstart), [официальный каталог MCP](https://www.xpoz.ai/.well-known/mcp/tools.json).
- Публикации аккаунта: `client.twitter.get_posts_by_author(username, start_date=..., end_date=..., response_type=ResponseType.PAGING)` / MCP `getTwitterPostsByAuthor`. Поиск публикаций: `search_posts(query, start_date=..., end_date=..., author_username=..., language=..., response_type=ResponseType.PAGING)` / `getTwitterPostsByKeywords`. До 100 ID можно получить через `get_posts_by_ids`. Поиск поддерживает фразы и Boolean; `from:`, `lang:`, `since:` и `until:` заменяются отдельными параметрами. [Twitter tools](https://docs.xpoz.ai/mcp/tools/twitter), [Python reference](https://docs.xpoz.ai/sdks/python/reference).
- Ответы на конкретный пост: `client.twitter.get_comments(post_id, fields=..., start_date=..., force_latest=...) -> PaginatedResult[TwitterPost]` / MCP `getTwitterPostComments`. Кавычные посты отдельно: `get_quotes(post_id)`. Для связи доступны `reply_to_tweet_id`, `conversation_id`, `quoted_tweet_id`; для текста и времени следует явно запросить `id`, `text`, `author_username`, `created_at`, а также нужные связи. [Twitter tools](https://docs.xpoz.ai/mcp/tools/twitter), [Python reference](https://docs.xpoz.ai/sdks/python/reference).

## Окно 48 часов и полнота

- [Обзор Xpoz](https://docs.xpoz.ai/introduction) заявляет скользящее окно данных 60 дней. Методы поиска/автора поддерживают `startDate` и `endDate` в формате `YYYY-MM-DD`; replies поддерживают `startDate`, но не `endDate`. Поэтому 48-часовые окна AstraFeed нужно дополнительно отфильтровать по точному `created_at` локально. `forceLatest=true` обходит кэш, но сам по себе не гарантирует полноту индекса. [Twitter tools](https://docs.xpoz.ai/mcp/tools/twitter).
- Для replies [официальная справка метода](https://docs.xpoz.ai/mcp/tools/twitter) указывает `responseType="paging"`, максимум 500 000 записей, 100 постов на страницу, `pageNumber` и `tableName`. [Схема пагинации](https://docs.xpoz.ai/mcp/pagination.md): первая страница возвращает `tableName`, `totalRows`, `totalPages`, `pageSize`, `pageNumber`; следующие запрашиваются по `tableName + pageNumber`. В SDK есть `has_next_page()` и `next_page()`. `tableName` временный; при его истечении запрос выполняется заново. По умолчанию `fast` даёт до 300 результатов и не годится для подсчёта всего треда. [Python pagination](https://docs.xpoz.ai/sdks/python/pagination).
- Признаки *неполной выборки результата запроса*: не пройдены все `totalPages`; превышен `limit`/лимит 500 000; ошибка/таймаут/истёкшая таблица; часть страницы не сохранена. Сравнение полученного числа replies с `reply_count` исходного поста может служить диагностикой, но равенство не доказано документацией. Важно: даже полностью пройденные `totalPages` подтверждают только полноту **набора, найденного Xpoz**, а не всех публикаций X. [Xpoz tracking](https://docs.xpoz.ai/tracking.md) прямо обещает *лучший* охват и свежесть при отслеживании, что означает различие покрытия между наблюдаемыми и произвольными запросами. Последние два предложения — вывод из документации, требующий проверки на выборке.

## Непрерывный сбор, лимиты и цена

- Xpoz предлагает `addTrackedItems` для ключевых слов и аккаунтов, чтобы регулярно пополнять индекс; Free включает 1 отслеживаемый элемент, Pro — 3, Max — 10. [Tracking](https://docs.xpoz.ai/tracking.md), [pricing](https://docs.xpoz.ai/pricing).
- [Webhooks](https://www.xpoz.ai/webhooks/) для новых совпавших постов и комментариев доступны в beta на Pro и выше; HTTPS endpoint, HMAC в `X-Xpoz-Signature`, ответ `2xx` за 10 секунд, 6 попыток доставки. Для Free указан polling. Этот механизм можно рассматривать после первоначальной проверки качества выборки.
- По [ценам Xpoz](https://docs.xpoz.ai/pricing): Free — 500 credits разово; Pro — $20/мес., 7500 credits/мес.; Max — $200/мес., 120 000 credits/мес. (годовая оплата дешевле). X-запрос стоит 2 credits; **каждая страница тоже отдельный платный вызов**. То есть при 5-минутном опросе только одного запроса постоянно Free хватит примерно на 250 вызовов, около 21 часа; replies для нескольких постов и страницы увеличивают расход. Это арифметическая оценка без кэша и деталей фактической тарификации.
- [Rate limits](https://www.xpoz.ai/rate-limits/): опубликованы 30 запросов/мин. и 2 одновременных запроса для Free, 120/мин. и 6 для Pro; `429` несёт `retry_after_ms`, 5xx допускают повторы. **В этой странице есть противоречие с [актуальной страницей credits](https://docs.xpoz.ai/pricing)**: она также описывает старую квоту в результатах и другое число tracking slots. Для бюджета опираться на страницу credits и данные аккаунта `getAccountDetails`; реальные лимиты подтвердить пробным запросом.

## Условия и решение для AstraFeed

- В [Terms of Use](https://www.xpoz.ai/terms/) для MCP есть короткая формулировка: “Use the Service to build, train, or enhance a competing product or dataset” в списке запретов. Применимость к AstraFeed, SDK и производным сводкам неоднозначна; перед публичным использованием данных в API/листинге разумно письменно уточнить разрешённый сценарий у Xpoz (`Hello@xpoz.ai`) и правила хранения/показа оригинальных постов.
- Продуктовый ориентир AstraFeed считает публикации основным доказательством сюжета, а комментарии отдельным последующим этапом. Значит технический первый шаг — проверить небольшой фиксированный набор X-аккаунтов и запросов за 48 часов, ссылку на каждый пост, полноту и задержку выборки, расход credits и отсутствие ложного «нулевого роста». После этого можно подключать replies как отдельный корпус реакций с `parent_post_id`, собственным coverage и без превращения числа ответов в число независимых источников сюжета. [Локальный ориентир](../product.md), [план MVP](../plans/community-pulse-mvp.md).

## Практический пробный сбор и решение

Проба 25 сентября 2026 года: запрос постов @WuBlockchain за 48 часов вернул 70 постов; запрос ответов к одному из них — 13 ответов. Общий поиск `crypto OR bitcoin OR ethereum OR solana OR defi` вернул 100 постов, только один — от наблюдаемых 16 авторов. При этом SDK сообщил `total_rows=0` для общего поиска, несмотря на 100 результатов. Повторный поиск через рабочий адаптер с исключением репостов вернул 139 пригодных публикаций. Поэтому `total_rows` быстрого режима нельзя считать надёжным доказательством полноты. Четыре вызова вместе израсходовали 8 из 500 разовых credits.

Решение владельца: свежие новости важнее полного частого обхода конкретных аккаунтов. AstraFeed опрашивает общий криптопоиск каждые 15 минут и 16 аккаунтов раз в 12 часов, пропуская X-профили Cointelegraph и The Block, уже представленные в RSS. Ответы читаются до трёх новых тредов в час и 70 тредов всего, кешируются навсегда в SQLite. Клиент останавливает платные вызовы при остатке 50 credits. За первые 24 часа расписание предусматривает не более 96 поисков (192 credits), 32 обходов аккаунтов (64) и 70 чтений ответов (140); остальное — резерв на изменения и ошибки. Эти лимиты относятся к Xpoz; LLM имеет отдельный бюджет.

Для включения нужны `XPOZ_API_KEY` в локальном `.env`/окружении и `xpoz_accounts` в конфигурации; рабочий `config.yaml` намеренно не отслеживается Git, а полный список из 16 аккаунтов приведён в `config.example.yaml`. Сам факт запуска с ключом тратит credits на первом сборе: один общий поиск плюс по одному запросу на каждый аккаунт. Контролировать остаток можно через бесплатный `getAccountDetails` или [панель Xpoz](https://xpoz.ai/usage).

Общий поиск хранится как один источник повестки для консервативного подсчёта каналов, но автор каждого поста сохраняется в ссылке и `channel_ref`. Посты 16 наблюдаемых авторов, найденные общим поиском, кладутся в их отдельные источники, поэтому последующий обход аккаунта не создаёт копию. Любой охват Xpoz остаётся неполным для сравнения суточного роста: API возвращает найденные индексом данные, а не доказательство отсутствия других постов X.
