# News-first Pulse: отчёт о готовности (2026-09-24)

Отчёт по [плану](../plans/news-first-pulse-agent-prompt.md). Готовность к демо **не достигнута
полностью**: на замороженной выборке не выполнены пороги точности отбора, объединения событий и
связей «комментарий → событие». Ниже — что сделано, результаты и причины.

## Что реализовано

- Конвейер `docs/research/news_pulse_*.py`: read-only снимок БД → сегменты поста (событие, позиция
  автора, перепечатка, реакция, промо) → LLM-классификация с кешем → группировка событий →
  связи комментариев → `pulse.json`, `brief.md`, `decisions.json`, `manifest.json`.
- События группируются жадными кликами без транзитивных склеек: детерминированные ключи
  (действие, объект, сумма в млн USD, дата с разрешением «вчера/сегодня») и LLM-судья на парах-
  кандидатах. Разные ETF (BTC/ETH), разные дни потоков и разные суммы — конфликт.
- Строки таблиц потоков ETF получают заголовок таблицы как контекст.
- Тема, упомянутая как фон (сравнение, цель свопа, риторический вопрос), не становится событием темы
  (`topic_role=context`).
- Обсуждение: только комментарии, называющие тему, или комментарии к постам с упоминанием темы.
- Распространение считается по уникальным публикациям: каналы, первоисточники, перепечатки.
- Бриф извлекающий: утверждения — дословные цитаты, числа считает код. Проверка
  `news_pulse_ground.py` сверяет каждое утверждение с БД; она подключена к оценке.

Мутационная проверка подтверждённости: подмена числа в цитате, неверный счётчик и ручная правка
brief.md (`test_grounding_check_catches_altered_number_and_edited_brief`); выдуманный пункт
«Коротко», чужое основание связи и связь с несуществующим событием даже после перерендера brief
(`test_grounding_checks_short_observations_and_discussion_basis`). Подмена любого числа раздела
«Изменения» ловится оценщиком (`test_forged_changes_fail_numeric_aggregates`).

Ревью pulse-codex после 5d888d5 (исправлено): сомнительная реплика в тематической ветке теперь
остаётся в обсуждении как `topic_level`, а не выпадает; «Изменения» считают комментарии темы
(`topic_comments`), а не все комментарии снимка; одинаковый текст в разные дни, соседние дневные
потоки с близкими суммами и одно действие разных акторов (Binance/Coinbase listing) больше не
склеиваются. Ограничение: после этих правок 21 запрос к LLM-судье не нашёлся в кеше
(прогоны arc 17, zec 4; режим `PULSE_REUSE=1`); пары засчитаны как «неясно» и остались раздельными —
метрики объединения на news-eval и news-tune не изменились.

Второй раунд ревью (после f06c8f2):
- Явно названные разные дни теперь не склеиваются даже при равной или округлённой сумме
  ($100M 21.09 / $100M 22.09; $143.7M / $144M). Соседний день допускается, только если одна из дат
  не названа в цитате и взята из даты публикации (`date_from_pub`).
- Разные акторы (Binance ZEC / Coinbase Zcash) больше не склеиваются детерминированно, в том числе
  через алиас объекта и одинаковый короткий текст («ZEC» от разных авторов). Это не жёсткий
  конфликт: строки не отличают второго актора от синонима (BitMine / $BMNR, hackers / attackers),
  поэтому такие пары решает LLM-судья.
- Числа «Изменений» про предыдущее окно (`previous_events`, `events_appeared/gone`,
  `previous_topic_comments`) сверяются с прогоном за это окно. Если такого прогона нет, результат
  unverified, а не pass.
- Проверка подтверждённости пересчитывает предикат основания связи по исходным данным: «повторяет
  формулировку» требует пересечения текста с событием, «реплика к посту» — комментарий под постом
  ровно этого одного события и о его предмете (тот же `replies_to_event`, что у связывателя), тезис
  автора — пересечение реплики или её цепочки ответов с тезисом. Связь с событием без id события
  не проходит; основание «по предмету единственного события родительского сегмента» удалено: оно
  давало связь с событием, которого нет в прогоне (в сохранённых прогонах не встречалось).

Ограничение: пары с разными акторами теперь идут к судье. В кеше нет 129 его вердиктов (режим
`PULSE_REUSE=1`, без сети), они засчитаны как «неясно». Поэтому pair-10 (BitMine / $BMNR) разделилась:
до исправления она склеивалась детерминированно, без проверки актора. Полнота объединения — 4/10.
Дозапрос вердиктов — платные вызовы, ждут решения.

## Оставшиеся ошибки (по news-eval; код под них не настраивался)

- Отбор: 5 постов по zec отнесены к новостям вопреки разметке (дайджесты и рекап-посты).
- Объединение: пересказы одного события разными словами без общей суммы/даты не склеиваются
  (pair-01, 02, 04, 08, 09); ложная склейка pair-12 — два поста markettwits об ETH с похожими ключами.
- Связи комментариев: реплики о тезисе автора поста привязываются к событию поста (4 из 4).
  Нужен отдельный шаг «комментарий к событию или к мнению автора».
- Выборка маленькая: это проверка демо, а не качества на всех данных.

## Воспроизведение

```bash
make news-pulse PULSE_DB=astrafeed.db TOPIC=zec WINDOW=2026-09-17..2026-09-19   # JSON + бриф
PULSE_REUSE=1 make news-pulse TOPIC=aave WINDOW=2026-09-09..2026-09-23          # только из кеша
make news-pulse-serve PULSE_DB=astrafeed.db   # GET /news-pulse?topic=zec&window=2026-09-17..2026-09-19
make news-pulse-eval PULSE_DB=astrafeed.db    # итоговая оценка → artifacts/news-pulse/eval
make news-pulse-tune PULSE_DB=astrafeed.db    # настроечная → artifacts/news-pulse/tune-eval
make news-pulse-ground PULSE_DB=astrafeed.db  # подтверждённость → artifacts/news-pulse/grounding
uv run pytest -q && uv run ruff check src tests
```
