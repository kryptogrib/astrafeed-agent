# Компоненты для Crowd Pulse: проверка перед сдачей

Проверено 23 сентября 2026: первичные README и указанный ниже исходный файл. Проекты не устанавливались и не запускались; качество на наших комментариях не проверено. Рекомендации ниже — оценка применимости к сроку 25 сентября.

## Что взять сейчас

- **[Label Studio](https://github.com/HumanSignal/label-studio)**: открытый интерфейс разметки текста, настраиваемые поля, импорт JSON/CSV, экспорт и показ предсказаний модели; лицензия Apache-2.0. Подходит для ручной проверочной выборки, а не готового анализа криптокомьюнити. Достаточно показывать пост, родительский ответ и комментарий; размечать тему, настроение, жалобу, вопрос и понятность контекста. Если установка тормозит работу, JSONL с теми же полями решает ближайшую задачу.
- Наш дизайн проверки: 100–200 комментариев из разных каналов/тем; отдельные сложные случаи — сарказм, реклама, короткие ответы, жалобы и тексты с отрицанием. Часть оставить для настройки промпта, часть заморозить для проверки. Одинаковые треды и копии не разносить между частями. Это наша методика, не встроенная гарантия Label Studio.
- Отчёт проверки: precision/recall жалоб с числом примеров, macro-F1 настроения, ошибки привязки к теме, доля отказов из-за нехватки контекста, доля невалидного JSON. Для маленькой выборки показывать сами ошибки и знаменатели; не обещать статистически устойчивую точность.

## News Radar: ориентир для новостного контекста

- **[README News Radar](https://github.com/OnixFireOne/news-radar)** описывает Telethon, SQLite/FastAPI, тематические алиасы, BGE-m3/ChromaDB, кластеризацию трендов и дайджесты со ссылками. Полезны идеи нормализованного сообщения и перехода от сводки к источнику. Заявленные охват и работа в реальном времени независимо не подтверждались.
- В [chroma_client.py](https://github.com/OnixFireOne/news-radar/blob/main/analyzer/chroma_client.py) действительно есть `find_duplicates`: попарное сравнение векторов и объединение групп через union-find. Это чтение реализации, не runtime-проверка; её пороги нельзя переносить на русские короткие комментарии без разметки пар.
- Для Pulse не копируем автоматическое объединение похожих мнений: «вывод работает» и «вывод не работает» — противоположные утверждения. Сходство темы не означает дубликат. В ближайшие два дня перенос стека эмбеддингов не нужен.
- В просмотренном корне репозитория лицензия не обнаружена: брать архитектурные идеи можно, перенос кода сначала требует проверки разрешения.

## Дедупликация: порядок внедрения

1. Сейчас: уникальный ключ `(platform, peer_id, message_id)` против повторного скачивания; редактирование обновляет исходное сообщение.
2. Сейчас: осторожно нормализованный текстовый хеш для групп одинаковых текстов; оригиналы, авторы, источники и счётчики сохраняются. Одинаковое «не могу вывести» от разных людей ещё не доказательство спама.
3. Позже: **[datasketch](https://github.com/ekzhu/datasketch)**, MIT: MinHash оценивает Jaccard-сходство наборов, LSH ищет кандидатов по порогу. Подходит для копипаста по словесным/символьным шинглам после проверки на размеченных парах; не определяет смысл или координацию авторов.
4. Альтернатива позже: **[simhash-py](https://github.com/seomoz/simhash-py)**, MIT: 64-битные отпечатки и поиск близких по расстоянию Хэмминга; есть C++-расширение. Сборка и совместимость с нашим окружением не проверены, поэтому не делаем зависимостью сдачи.

Минимальная метрика дедупликации: отдельно повторные загрузки, группы одинакового текста и доля сообщений в таких группах. Если появится near-dedup, вручную проверить precision объединений и показывать raw count рядом с числом групп; независимость авторов не следует из количества уникальных текстов.
