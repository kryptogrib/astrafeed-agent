# Crowd Pulse: что переиспользовать и на кого смотреть

Проверено по первичным источникам 23 сентября 2026 года. Это подборка ориентиров, а не результат установки и тестирования проектов. Направление: [продуктовый ориентир](../product.md).

**Рекомендация: сохранить движок AstraFeed и достроить слой Pulse.** Готовые продукты полезны как образцы метрик и ответа; открытые проекты — как источники отдельных решений. Перенос целого чужого стека сейчас создаёт отдельную миграцию до проверки ценности демо.

## Продуктовые ориентиры — идеи, не готовый код

| Проект | Что уже есть по документации | Что взять для Crowd Pulse |
|---|---|---|
| [Santiment Social Trends](https://academy.santiment.net/sanbase/social-trends/) | Почасовой Top 10, всплески относительно двухнедельной нормы, объяснения трендов, bullish/bearish summaries | Главный ориентир для Trending → раскрытие темы. Показывать изменение относительно нормы и аргументы сторон. |
| [Santiment Trending Stories](https://academy.santiment.net/metrics/trending-stories/) | API возвращает заголовок, summary, запрос к исходным постам, score, доли bullish/bearish и связанные токены; есть выбор Telegram/X | Близкий пример контракта ответа: сводка связана с запросом к основаниям. Заявления поставщика о скорости не доказывают преимущество Crowd Pulse — нужен свой кейс с временными отметками. |

## Открытые проекты — кандидаты на разбор отдельных решений

### Harken — компактный образец social listening

[Репозиторий и README](https://github.com/VladUZH/harken), [MIT LICENSE](https://github.com/VladUZH/harken/blob/main/LICENSE).

Адаптеры источников → общий `Mention` → дедупликация по хешу → sentiment/themes → SQLite → dashboard/CLI. В README описаны Reddit, X, RSS и другие источники, baseline из предыдущих полных окон, минимальный объём выборки, cooldown и исключение backfill из новых уведомлений.

**Разобрать:** границу адаптера, нормализованное сообщение, курсоры, правила повторных сигналов. Это особенно полезно для последующего расширения за Telegram.

**Граница:** Telegram и Discord не перечислены среди поддерживаемых источников. Для X нужен подходящий API-доступ, для Reddit — OAuth. Качество локального sentiment на криптосленге и жалобах нами не проверялось; описанная автором небольшая регрессионная выборка не заменяет нашу разметку. Зрелость и работоспособность интеграций требуют отдельной проверки.

### OpenMagpie — ориентир для будущего Watch

[Репозиторий и README](https://github.com/obris-dev/openmagpie), [LICENSE](https://github.com/obris-dev/openmagpie/blob/main/LICENSE).

`Feed` собирает сообщения один раз, несколько `Watch` используют этот поток; цепочка `semantic_filter → webhook/log` отбирает релевантные сообщения. Есть мгновенная и пакетная доставка, журнал попыток. По README доступны X, YouTube, Reddit, HN и RSS; UI ещё планируется.

**Разобрать:** разделение сбора и пользовательских подписок, журнал обработки и доставки, дедупликацию у получателя. Это ориентир для этапа после MVP, не повод сразу строить весь Watch.

**Граница:** X использует неофициальный способ с cookie браузерной сессии; его нельзя считать готовым надёжным коннектором без проверки. В корневом LICENSE — Apache 2.0 с отдельными условиями для `ee/` и сторонних компонентов: при заимствовании смотреть конкретные файлы. Production-зрелость не проверена.

### BettaFish — образец аналитического отчёта

[Репозиторий](https://github.com/666ghj/BettaFish): многоагентный анализ общественного мнения, отдельные InsightEngine, QueryEngine и ReportEngine, примеры отчётов.

**Разобрать:** структуру отчёта, вопросы к данным и способ организации объяснений. Для короткого Pulse весь многоагентный стек выглядит избыточным — это наша оценка применительно к MVP. GitHub указывает GPL-2.0; перенос кода требует отдельной проверки условий, поэтому сейчас полезнее как ориентир, чем как основа миграции.

## Готовые компоненты

| Компонент | Практическое применение | Когда |
|---|---|---|
| [Label Studio](https://github.com/HumanSignal/label-studio) | Разметка текста; открытая версия Apache 2.0. Подготовить проверочную выборку с метками «жалоба», sentiment, тема и тип сообщения | Сейчас: проверка 150–200 комментариев важнее добавления сложного анализа |
| [PRAW: Comment Extraction](https://praw.readthedocs.io/en/stable/tutorials/comments.html) | Готовая работа с деревьями Reddit-комментариев. Доступ к Reddit API решается отдельно | После демо, когда потребуется Reddit |
| [BERTopic](https://github.com/MaartenGr/BERTopic) | Тематическое моделирование на embeddings и c-TF-IDF; [MIT](https://github.com/MaartenGr/BERTopic/blob/master/LICENSE) | Позже: эксперимент по обнаружению новых тем, если закрытый список начинает ограничивать продукт |

BERTopic не заменяет классификацию жалоб и не обязателен для первого Pulse. Любое заимствование компонента следует проверять на нашем языке, сленге и объёме данных.

## Порядок действий

1. Сверить форму Trending/Pulse с Santiment; оставить основания, ограничения выборки и ранние жалобы в центре продукта.
2. Просмотреть Harken для baseline и адаптеров, перенести только подходящие принципы в текущий движок.
3. Разметить проверочную выборку, измерить ошибки жалоб и тематической привязки, собрать Telegram-демо.
4. После демо выбирать один новый источник; OpenMagpie изучить перед проектированием Watch.

Внешние проекты не снимают собственную задачу Crowd Pulse: корректно связать комментарии с темой и контекстом, отличить жалобу от шутки/рекламы, посчитать изменения на неполных данных и дать проверяемые основания ответа.
